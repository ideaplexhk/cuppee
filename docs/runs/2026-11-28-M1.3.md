# Run 2026-11-28: M1.3 Port services and tests to Postgres

- Trigger: nightly (06:17 HK run)
- Branch and PR: agent/M1.3-port-postgres, PR #7
- Result: shipped for review

## Done
- The server, the seed script and every test now run on PostgreSQL through `pg`. `node:sqlite` is gone.
- `server/src/db.ts`: a small wrapper over a `pg` pool (`query`, `one`, `all`, `run`, `tx`, `afterCommit`).
  BIGINT (epoch-ms times, counts, sums) and NUMERIC (money) come back as JavaScript numbers, as they did on SQLite.
- Each HTTP request runs in one `SERIALIZABLE` transaction, retried from the start (up to 10 times, exponential
  backoff with full jitter, capped at 500 ms) when Postgres reports a conflict. On SQLite each request ran synchronously and could not overlap another one; this keeps that
  guarantee now that requests overlap on a pool.
- Same error behaviour as before: an API error (`HttpError`) still commits what the request wrote first (wrong OTP
  attempts are still counted); the routes that were all-or-nothing (`tx()` around link cup, card visit, redeems,
  stand confirm, POS order, each stand event) still are: inside a request, `tx()` becomes a savepoint.
- The OTP SMS is sent after commit (`db.afterCommit`), so a retried or rolled-back request never texts a dead code.
- Data modules: `$n` placeholders, quoted camelCase aliases (Postgres folds unquoted ones to lower case),
  `ON CONFLICT DO NOTHING` for SQLite's `INSERT OR IGNORE`, the `otp_codes.id` column instead of `rowid`,
  `NULLS LAST` for the stamp-card order, `COLLATE "C"` on name sorts to keep SQLite's byte order.
- `npm start` and `npm run seed` apply pending migrations first (the runner is locked, so two instances are safe).
  `DB_PATH` is replaced by `DATABASE_URL`, which is now required.
- Tests: each test file gets a throwaway schema with the migrations applied. They need `DATABASE_URL` and fail
  without it (no silent skip, locally or in CI). The schema test compares Postgres against
  `test/fixtures/v0.1-sqlite-schema.json`, captured from the old SQLite schema before it was removed.
- New `test/postgres.test.ts` (15 tests): a dropped idle connection does not stop the server; 20 cafés reading and confirming cups at the same moment, with feed polling,
  all succeed; concurrent stamp-card and reward redeems spend once; one phone signing up
  twice at once makes one member; wrong OTP attempts still count; a failed cup link does not burn the SUN counter;
  numbers stay numbers; tx() rollback, keep-on-error, nested savepoint and retry; after-commit work is dropped on
  rollback, also when only a nested tx() is undone; the backoff schedule; the seed script loads and is safe to run twice. New guard tests: no `node:sqlite`, no SQL outside
  `src/data/`, no `?` placeholders in data modules.
- Checked by breaking the code on purpose: plain `BEGIN` instead of `SERIALIZABLE` fails the bean-redeem, sign-up
  and retry tests (the stamp-card race did not reproduce reliably without it, so the bean test is the one that
  guards double spending); dropping keep-on-error fails the OTP-attempts test.
- Review round 1 found that unrelated requests at the same moment (separate cafés) could fail with HTTP 500:
  Postgres reports false serialization conflicts on small tables, and the first retry schedule (5 tries, ~10 ms
  apart) gave up too soon. Fixed with the longer backoff above; the new 20-café test fails on the old schedule
  every time and passed 8 runs out of 8 on the new one.
- Review round 2 found that a dropped idle Postgres connection (restart, failover) crashed the API: the pool had no
  'error' listener. Fixed and tested (the test kills an idle backend; without the listener the test process dies).
- README, ARCHITECTURE and `.env.example` updated.

## Decisions I made myself
- One serializable transaction per request (rather than adding locks to each service) so the old "one request at
  a time" behaviour holds everywhere without auditing each query.
- No change to `package.json` scripts, `scripts/` or CI (owner-reviewed); CI already runs a Postgres 16 service.
- Diff is above ~500 lines, mostly the mechanical async/`$n` rewrite of the data modules and the schema fixture.
- A stand-event batch now runs in one request transaction; if one event hits an unexpected server error, the whole
  batch is undone and the stand retries it (event ids make the retry safe). Before, earlier events stayed saved.
