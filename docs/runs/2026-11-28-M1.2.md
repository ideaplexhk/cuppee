# Run 2026-11-28: M1.2 Postgres schema and migrations

- Trigger: on demand
- Branch and PR: agent/M1.2-pg-schema, PR #6

## Done
- `server/migrations/0001_init.sql`: PostgreSQL version of today's 14 tables, same columns. Deliberate differences:
  money as `NUMERIC(10,2)` (not floating point), an `id` on `otp_codes` (Postgres has no rowid), 0/1 flags kept as
  `INTEGER` with a CHECK, times kept as epoch-ms `BIGINT`, and a CHECK that a stamp ledger row names its café.
- `server/src/migrate.ts`: tiny runner. Applies `NNNN_name.sql` files in order, each in its own transaction, records
  them with a checksum in `schema_migrations`, refuses an applied file that was later edited, and takes an advisory
  lock so two instances can't migrate at once. CLI: `DATABASE_URL=... node src/migrate.ts`.
- `pg` added as the server's first runtime dependency (the agreed driver), plus `@types/pg`.
- `server/test/migrate.test.ts` (7 tests, real Postgres, a throwaway schema per run): applies once and is idempotent;
  tables and columns match the SQLite schema exactly; every café-owned table has a required `cafe_id`; stamp rows
  need a café; money is numeric; an edited migration is refused; a failing migration rolls back and is not recorded.
- Without `DATABASE_URL` the Postgres tests are marked skipped locally; in CI (`CI` set) a missing URL fails the run.
- `server/.env.example` and `docs/ARCHITECTURE.md` updated.
