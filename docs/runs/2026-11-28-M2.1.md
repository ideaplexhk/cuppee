## Done
- PR #7 (M1.3, Postgres port) resumed. A fresh reviewer round asked for one fix: the run report wording implied the
  agent may merge on its own. Reworded; the next round passed on 6acd6fb and CI is green. Marked ready. **Merging

- M2.1: every app string now lives in `app/src/lib/i18n/en.ts` and `zh-HK.ts` (151 keys).
  - `src/lib/i18n/core.ts`: plain TS (translate, placeholders, language detection, current language for errors
    raised outside React).
  - `src/i18n.tsx`: `LanguageProvider`, `useT()` and a `LanguageSwitch` (English / 繁體中文).
  - The switch is on the member profile, the sign-in screen, staff login and the staff counter header.
  - Start-up language: a `?lang=` link (web) first, then the saved choice, then the device language, then English.
    The choice is saved on the device under `lang`, which matches the screenshot harness in PR #4.
  - Dates follow the language. API "offline" errors and NFC errors are translated.
  - Server errors are translated by the stable code the API sends (`error.<code>`, 29 codes). An unexpected code
    falls back to the server's own text, then to a generic error. On the counter, a failed cup read now shows its
    technical code in brackets instead of an English reason inside a Chinese sentence.
  - `src/storage.ts`: the SecureStore/localStorage helper moved out of `session.tsx`, so the language can use it.
- Tests (`app/test/i18n.test.ts`, 13 tests):
  - fail if a key is missing or empty in either language, or if zh-HK is still English;
  - fail if the placeholders differ between the two languages;
  - fail if a screen uses an unknown key, or if English text is hard-coded in any screen, component or app module;
  - fail if the server can send the app an error code that has no `error.<code>` text. A short list of codes
    for machines only (stand, POS webhooks) is exempt;
  - cover language detection and fallback.
  - Checked by mutation: putting back a hard-coded title, or deleting a zh-HK key, makes them fail. TypeScript also
    refuses a missing zh-HK key.
