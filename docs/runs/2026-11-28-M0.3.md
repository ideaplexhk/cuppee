## Done
- Earlier in this run: fixed red CI on PR #3 (M0.2, `react-dom` pinned to 19.3.0), reviewed, merged.
- `scripts/screenshots.py` now runs end to end:
  - seeds a throwaway dev database and starts the API on it;
  - builds the Expo web export (`expo export --platform web`) and serves it locally with SPA routing;
  - signs in through the API (member via dev OTP for a fake number, staff via the seeded dev PIN) and puts the
    session into browser storage, so signed-in screens render signed in;
  - saves `screenshots/<lang>/<size>/<name>.png` at 1280×800 and 1180×820 for `en` and `zh-HK`;
  - fails (non-zero exit) if a screen redirects elsewhere, renders blank or cannot reach the API.
- `scripts/screens.json` has an `auth` field per screen (`none` / `member` / `staff`) and now also covers the map and
  profile tabs (7 screens, 28 PNGs).
- Pure helpers are unit-tested (`scripts/test_screenshots.py`, 8 tests); `verify.sh` runs them on every run.
- CI installs Python Playwright + Chromium and runs `verify.sh --screens`; the PNGs are uploaded as the `screenshots`
  artifact on every PR.
- Added `react-native-web` ~0.21.4 (Expo SDK 58.1 set) to the app: Expo needs it for the web build.
- Bug found by the harness and fixed: the staff home screen redirected to staff login before the stored session had
  loaded, so a tablet opened straight on `/staff` bounced to the login screen. It now waits for the session.
